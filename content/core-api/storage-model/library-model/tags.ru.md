# Теги

## Место в модели

- `Tag` является отдельной сущностью уровня библиотеки и НЕ является `field_type`.
- Записи контента связываются с тегами через ассоциацию many-to-many.

## Сущность Tag

- `id` (`system`) - неизменяемый идентификатор тега.
- `library_id` (`system`) - библиотека-владелец.
- `key` (`system` или managed) - стабильный внутренний ключ.
- `label` (`user_editable`) - отображаемое пользователю имя тега.
- `color` (`user_editable`, optional) - визуальный цветовой маркер.
- `icon` (`user_editable`, optional) - визуальный икон-маркер.
- `created_at` (`system`) - момент создания.
- `updated_at` (`system`) - момент обновления.

## Связь с контентом

- Связь контента с тегами ДОЛЖНА поддерживать несколько тегов на одну запись.
- Назначение тегов редактируется в отдельном блоке `Tags` внутри карточки записи.
- UI назначения тегов ДОЛЖЕН/РЕКОМЕНДУЕТСЯ поддерживать выбор существующих тегов и создание новых inline.

## Правила редактирования

- Переименование тега обновляет `label` без переписывания записей контента.
- Удаление тега ДОЛЖНО удалять связи с контентом, но НЕ ДОЛЖНО удалять контент.
- Объединение тегов МОЖЕТ поддерживаться и ДОЛЖНО сохранять связи с контентом.

## Import/Export и синхронизация

- Таксономия тегов ДОЛЖНА переноситься вместе с экспортом/импортом библиотеки.
- Данные тегов и связи тег-контент ДОЛЖНЫ синхронизироваться в sync-режиме.
